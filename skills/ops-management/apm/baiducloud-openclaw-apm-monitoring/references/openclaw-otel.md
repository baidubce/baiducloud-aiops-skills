# OpenClaw Official OTel Integration Reference

## Approach and Validated Baseline

On 2026-09-10, real Gateway chat requests using **OpenClaw 2026.9.3 + official diagnostics-otel 2026.9.3 + Node 26.8.2** verified model I/O, per-call token usage, positive model-call duration, and trace parent/child relationships. The validation used the native runtime without modifying OpenClaw or plugin source code.

Use this as the validated baseline and match the plugin to the stable core version installed on the target machine. Do not describe an untested newer release as already validated. Use only the official `@openclaw/diagnostics-otel`; this integration does not require the Langfuse SDK, Langfuse Bridge, or session-file changes.

## Endpoint and Auth

| Input | Final tracesEndpoint |
| --- | --- |
| `https://collector.example.com` | `https://collector.example.com/api/public/otel/v1/traces` |
| `https://collector.example.com/` | `https://collector.example.com/api/public/otel/v1/traces` |
| `https://collector.example.com/api/public/otel/v1/traces` | Use this exact complete URL. |
| `https://collector.example.com/custom/v1/traces` | Use this exact complete URL without appending another path. |

Example domains are placeholders. An endpoint containing a path is treated as a complete ingestion URL. If a receiver instead provides a base URL with a path prefix, resolve the complete trace URL from its documentation before running setup; do not blindly apply the origin-only expansion rule.

`headers.Authorization` accepts the complete auth value, preserving the receiver's prefix and encoding. Do not convert it into Langfuse public/secret keys. `Authorization` and `Authentication` are different headers, not capitalization variants. This skill does not automatically probe or rotate authentication protocols.

Obtain the matching endpoint and auth from the [BCM LLM application monitoring access page](https://console.bce.baidu.com/bcm/#/bcm/llm/apmApplication/access-doc). This skill targets its LLM/Langfuse-compatible ingestion route; do not mix in authentication formats from a different generic OTLP route.

## Versions and Managed Installations

OpenClaw 2026.9.3 requires Node `>=24.16.0 <25 || >=26.1.0`. Check the actual Node paths used by both the CLI and Gateway service. Updating an interactive shell's PATH does not change an existing launchd/systemd service command.

For installations older than the baseline, create an official backup and update using the installation's supported method:

```bash
openclaw backup create --no-include-workspace --verify --output '<private-backup-archive-path>'
openclaw update --tag 2026.9.3 --yes
openclaw --version
openclaw gateway status
```

Resolve Node compatibility before updating; the official installer can provide a supported runtime. When selecting a newer stable release, review its official release and migration notes first, then use matching core/plugin versions. Do not run `doctor --fix` to change unrelated settings or reopen a migrated database with an older binary.

For Docker, Nix, or centrally managed installations, follow the existing image or declarative configuration workflow. The script does not edit images, Nix source files, or service definitions. Merge the equivalent settings below through the existing deployment process. Do not change a host-side `openclaw.json` that the container never reads.

The exact plugin installation form is:

```bash
openclaw plugins install npm:@openclaw/diagnostics-otel@2026.9.3 --pin
openclaw plugins enable diagnostics-otel
```

The setup script uses the CLI's `--force --accept-capabilities` when installing or replacing this official plugin. It does not bypass blocking policies or turn warnings into successful validation. Stop and report a missing package, failed download, installation policy block, or version mismatch at that step; do not switch to an unknown source.

On native Windows, `--cli` can point to `openclaw/openclaw.mjs` inside the npm installation, which the script launches with Node. Do not build a shell command containing credentials to execute a `.cmd` shim. macOS, Linux, and WSL can use `openclaw` from PATH.

## Configuration File and Default Settings

The settings below are generated by `buildPatch()` in [scripts/configure.mjs](../scripts/configure.mjs). They are merged into the **active OpenClaw configuration file**, usually `~/.openclaw/openclaw.json`. A profile, `OPENCLAW_STATE_DIR`, or `OPENCLAW_CONFIG_PATH` can change the location. Run this on the actual Gateway host, under its runtime account and profile, to resolve the file:

```bash
openclaw config file --json
```

The script uses `openclaw config patch --stdin` and `--replace-path diagnostics.otel.headers` to merge the configuration while replacing old telemetry headers. Replace the example endpoint/auth with the user's values. This is a merge fragment, not a replacement for the whole configuration file.

```json
{
  "plugins": {
    "entries": {
      "diagnostics-otel": { "enabled": true }
    }
  },
  "diagnostics": {
    "enabled": true,
    "otel": {
      "enabled": true,
      "tracesEndpoint": "https://collector.example.com/api/public/otel/v1/traces",
      "protocol": "http/protobuf",
      "headers": { "Authorization": "REPLACE_WITH_COMPLETE_AUTH" },
      "serviceName": "openclaw",
      "traces": true,
      "metrics": false,
      "logs": false,
      "sampleRate": 1,
      "captureContent": true
    }
  }
}
```

### Message and Context Content Capture

The relevant switch is **`diagnostics.otel.captureContent=true`**, under `diagnostics.otel`, not the plugin's own `config`. It enables bounded, redacted model input/output messages and tool arguments/results. It does not guarantee I/O on every span and is not an unrestricted system-prompt or internal-reasoning export switch.

Verify this setting without printing credentials:

```bash
openclaw config get diagnostics.otel.captureContent --json
```

Restart the Gateway after applying the configuration. For a real request, inspect `gen_ai.input.messages`, `gen_ai.output.messages`, `gen_ai.tool.call.arguments`, and `gen_ai.tool.call.result` in the raw spans. A context-related span name alone does not prove that model message content was captured.

### Other Defaults and Merge Behavior

- `tracesEndpoint` is the final URL; OpenClaw does not append `/v1/traces`. The shared `endpoint` setting appends signal paths, so this integration uses `tracesEndpoint` explicitly.
- `sampleRate=1` is for onboarding verification. Users can lower it later. Plugin buffering, content limits, and provider capabilities can still limit available data.
- `metrics=false` and `logs=false` disable only the plugin's additional metric/log signals; they do not remove token attributes from traces.
- Append the native plugin to an existing `plugins.allow`. If no allowlist exists, do not create a one-plugin allowlist that could disable existing model providers. Remove only this plugin from an existing `plugins.deny`.
- Disable only an existing `langfuse-bridge`; retain its installed files and other agents' observability settings.
- `configure.mjs --check` checks the default content-capture setup. If the user explicitly chooses metadata only, manually use `captureContent=false` and verify metadata without treating absent message bodies as a failure.

## Restart and Configuration Recovery

By default, the script returns `restartRequired=true` after configuration without restarting the Gateway executing it. Inside an OpenClaw session, prefer the Gateway's restart tool. An independent host process can use `--restart`. After restarting, run `configure.mjs --check` to verify that the plugin is `loaded` and the Gateway is healthy.

The script does not change `.env` or shell profiles; auth is stored in the restricted active configuration. The backup is an exact copy of the **active configuration file**, preserving JSON5 syntax and `$include` references. It is not a full session database backup or a cross-version rollback archive.

If configuration fails, inspect the last completed stage and backup path. The official patch command validates changes first. If plugin installation succeeded but the later configuration patch failed, the plugin may remain installed; report that state instead of blindly reinstalling it.

Before rollback, check for configuration changes made since the backup. Restore the backup content with mode `0600`, run `openclaw config validate --json`, and restart through the original service mechanism. Do not overwrite subsequent user changes. Restoring configuration does not uninstall a newly added plugin or roll back databases or external `$include` files.

## Ingestion Verification and Known Limits

`verify.mjs` invokes the existing real model with one request that does not use tools. It does not create manual OTLP spans. A completed request proves only native local execution; a `loaded` plugin is also local evidence. Without receiver evidence, `apmReceiptVerified` must remain `false`.

When APM access is available, inspect these raw fields:

| Object | Expected evidence |
| --- | --- |
| Resource | `service.name=openclaw`, or the name explicitly chosen by the user. |
| `openclaw.model.call` | `gen_ai.request.model` / `gen_ai.response.model`, `gen_ai.input.messages`, `gen_ai.output.messages`, and start/end timestamps. |
| Per-call usage | `gen_ai.usage.input_tokens` and `gen_ai.usage.output_tokens`. Cache tokens are an input subset; do not add them again. |
| Reasoning detail | Native `openclaw.model_call.usage.reasoning_output_tokens`; the Collector can normalize it to `gen_ai.usage.reasoning.output_tokens`. It is an output subset. |
| Tool execution | `gen_ai.tool.name`, `gen_ai.tool.call.id`, `gen_ai.tool.call.arguments`, and `gen_ai.tool.call.result`. |
| Structured messages | Preserve and parse `parts[].type=tool_call` and `tool_call_response`, not just text parts. |
| Trace structure | Unique span IDs; every nonempty parent span ID resolves within the same trace. |

The official exporter also emits the run-level `openclaw.model.usage` summary. On the native request path with individual `model.call` usage, this summary supports reconciliation. The APM Collector should classify this exact summary span under native scope `openclaw` as `step`, preserving its original attributes while excluding it from LLM token totals and model-call counts.

A local Collector fix for this classification and reasoning mapping passed regression checks on 2026-09-10. **This skill package does not include the server patch or imply that the target APM has deployed it.** Query's `tokenUsage` sums only `llm` spans; its legacy `tokens` field may still ignore kind. Do not fix server-side totals by deleting native summaries, clearing token attributes, or dividing totals by two.

If raw input messages exist but the input summary displays `<<<BEGIN_OPENCLAW_INTERNAL_CONTEXT>>>`, or raw tool parts exist but the page omits them, inspect Query's display parsing. Reinstalling the exporter is unnecessary. The official 2026.9.3 exporter also filters some session identity fields; this skill neither requires session/user IDs nor fabricates them.

Streaming token usage is generally available after the provider returns final usage. Interrupted streams or providers without usage cannot guarantee complete totals. Instantaneous spans, such as context events, can legitimately have zero duration; distinguish them from model-call spans.

## Troubleshooting

| Symptom | Next action |
| --- | --- |
| `localConfigReady=false` | Resolve the reported version, plugin, configuration, or Gateway health issues without printing auth. |
| CLI settings look correct but the Gateway is unchanged | Check the service account, profile, configuration path, Node path, and actual restart. Do not start a second Gateway. |
| `OTEL_TRACES_EXPORTER=none` | Check the Gateway service environment and remove the trace-disabling setting. The CLI environment check does not reveal the entire service environment. |
| 401 / 403 | Check the complete auth, header contract, endpoint, account, and region. Do not re-encode auth or retry indefinitely. |
| Root GET returns 404 | This does not prove ingestion failure; writes use protobuf POST to the trace path. |
| Native POST to the trace path returns 404 | Check the complete ingestion URL for duplicate `/v1/traces` or a mixed-up generic OTLP route. |
| No trace after the local reply completes | Inspect sampling, exporter errors, network connectivity, and the original request's time window. Allow receiver processing before checking again. Environment-specific list delays are not an OpenClaw compatibility defect. |
| Raw spans exist but tokens are duplicated or content is missing from the page | Check server classification and Query parsing as described above, instead of repeatedly changing correct collection settings. |
